| Provider | Storage estimate | TTS estimate | Current release compatibility |
| --- | ---: | ---: | --- |
| AWS S3 Standard + Polly Standard | About $0.23/month per 10 GB in us-east-1; requests/egress extra and region rates differ. | $4/M characters outside eligible free usage; AWS lists 5M Standard chars/month free for eligible accounts. | Supported directly. Use a narrowly scoped AWS runtime identity for the private bucket prefix and Polly synthesis. |
| Backblaze B2 + Polly Standard | About $0.0695/month per 10 GB at $6.95/TB-month; transactions free, egress free up to 3x stored average. | Same Polly rates as AWS above. | B2 S3 API supports AES256 SSE-B2 and presigned URLs. Google requires a new TTS adapter and independent credentials. |

#### Setup plan (not executed)

1. Choose an AWS region with data-location and latency requirements in mind.
   For an Africa-local configuration, af-south-1 supports Polly Standard; use
   the same S3 region where practical and check its current S3 rate in the AWS
   calculator. The us-east-1 S3 estimate above is only a price reference.
2. Create a private S3 bucket with Block Public Access, default SSE-S3 AES-256,
   and a bucket policy denying non-TLS access. Use only a dedicated non-root
   runtime identity. Allow s3:PutObject, s3:GetObject and s3:DeleteObject only
   for the audio prefix; allow polly:SynthesizeSpeech only in the selected
   region. The current production VPS is outside AWS; first check for an
   existing approved workload identity. If none exists, a dedicated access key
   must be created, scoped to these actions, stored only in the approved
   root-readable runtime secret file and rotated. Never put it in Actions,
   source control, or the deploy workflow.
3. After explicit approval, add AUDIO_STORAGE_BUCKET, AUDIO_STORAGE_REGION,
   and AUDIO_TTS_REGION to runtime configuration; keep them unset before then.
   Do not print secrets during checks or restart unrelated processes.
4. Current code limits each TTS request to 3,000 characters, requires durable
   idempotency keys, and records generated character counts. There is no
   monthly character hard cap yet. A proposed $1/month Polly AWS Budget with
   notifications at 50%, 80%, and 100% is a useful alarm, not an immediate
   spending stop. Before enabling production synthesis, decide and implement a
   concurrency-safe monthly character cap; proposed QA starting limit is
   100,000 characters/month (at most $0.40 at $4/M outside free usage). Keep
   Polly permissions disabled until that cap and budget alarms are ready.
5. Review storage growth and retention: audio assets currently have no automatic
   expiry. Do not set lifecycle deletion until campaign references and retention
   requirements have an approved policy.
6. B2 path: private bucket with default SSE-B2 AES-256 and a bucket-scoped
   application key. Before configuring the B2 key, add reviewed storage-specific
   credential support; do not put it in shared AWS credential variables while
   Polly uses the same chain. Configure endpoint
   https://s3.<region>.backblazeb2.com, bucket/region and path-style as
   validated by integration tests.
7. R2 path: private bucket and least-privilege token. A reviewed adapter change
   must omit the unsupported SSE request header for R2 only, relying on R2's
   documented provider-managed AES-256 at-rest encryption. Configure endpoint
   https://<account-id>.r2.cloudflarestorage.com, region auto, and verify
   short-lived signed GETs use the S3 API hostname.
8. Google TTS path: add a TextToSpeechProvider adapter with explicit voice
   mapping and MP3 output; use a separate least-privilege service identity,
   quotas, budget alerts and a hard usage cap. No credentials in code/repo.
9. Test first in a non-production account: upload synthetic audio, inspect
   private access/encryption, verify signed-link expiry, synthesize one short
   sample and select it on a disposable QA campaign. Once approved and deployed
   through CI/CD, repeat those checks with QA accounts.

This plan is informational. No provider account, bucket, token, secret, paid
request, or production setting was created or changed for this review.

## Implementation notes

`@truevine/audio` defines file validation, the storage and TTS ports, an
S3-compatible storage adapter, and an Amazon Polly adapter. The API supports
tenant-authorized listing, browser recording/file uploads, TTS, short-lived
playback links and usage/audit records. Campaign creation/update can select an
audio asset only inside that campaign's organization; this records selection
but does not start call execution. The essential UI is `/app/audio` and the
audio selector on `/app/campaigns`.

The migration adds composite organization keys/FKs, idempotency operations and
an append-only usage trigger. Its SQL and controlled migration plan passed the
hosted migration rehearsals. Runtime bucket, AWS region and credential-chain
configuration is still absent, so live recording, playback and TTS remain
blocked until platform configuration is approved and installed. Production
deployment is complete; those features are not enabled or verified.
