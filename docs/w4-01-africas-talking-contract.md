# W4-01 Africa's Talking voice contract

- The official Node SDK uses `https://voice.sandbox.africastalking.com/call` for sandbox and `https://voice.africastalking.com/call` for production. The form-encoded POST includes `username`, `from`, `to` and optional `clientRequestId`, with the API key in the `apikey` header. Sandbox uses the `sandbox` username. The source must be a provider-issued voice number, and numbers use international format. [SDK URL selection](https://github.com/AfricasTalkingLtd/africastalking-node.js/blob/master/lib/common.js) · [SDK voice request](https://github.com/AfricasTalkingLtd/africastalking-node.js/blob/master/lib/voice.js) · [SDK setup](https://github.com/AfricasTalkingLtd/africastalking-node.js/)
- The SDK accepts HTTP 200 or 201 for initiation and passes the body through. The provider shows a Queued result with a provider call/session identifier. Queuing acknowledges acceptance and does not establish that the recipient answered. Preserve the provider identifier for reconciliation. Confirm the complete Voice error and result schema before enabling dispatch. Treat transport failures, ambiguous bodies and timeouts as reconciliation cases. The documentation describes `clientRequestId` as correlation metadata, so it cannot justify retrying a paid operation. [SDK voice request](https://github.com/AfricasTalkingLtd/africastalking-node.js/blob/master/lib/voice.js) · [Queued response example](https://help.africastalking.com/en/articles/1142495-why-can-t-i-see-a-call-on-my-at-dashboard) · [Official PHP SDK](https://github.com/AfricasTalkingLtd/africastalking-php)
- The SDK uses the read-only application-data lookup at `https://api.sandbox.africastalking.com/version1/user` or `https://api.africastalking.com/version1/user`. Use this to verify application credentials without placing a call. This check establishes application access. Voice-number ownership, routing readiness and callback readiness require separate evidence. [SDK application method](https://github.com/AfricasTalkingLtd/africastalking-node.js/blob/master/lib/application.js) · [SDK URL selection](https://github.com/AfricasTalkingLtd/africastalking-node.js/blob/master/lib/common.js)
- Voice callbacks can require XML instructions. Event notifications carry call lifecycle information, including ringing, bridged, completed and failure states. The help article on verification describes API request credentials and SIP source allowlisting but does not specify an HTTP callback signature, canonicalization or replay mechanism. Confirm a supported HTTP verification mechanism or approve compensating controls before allowing callbacks to drive authoritative state. [Voice callback example](https://help.africastalking.com/en/articles/5947707-how-do-i-receive-calls-on-my-sip-phone-or-any-ip-phone) · [Voice event parameters](https://help.africastalking.com/en/articles/2948521-understanding-parameters-used-in-a-call) · [Provider verification guidance](https://help.africastalking.com/en/articles/5947646-how-can-ensure-that-the-post-request-to-my-callback-url-is-coming-from-africa-s-talking-and-not-some-other-place)
- The official Voice SDK exposes queue status by phone number. It does not establish per-session status polling or remote hang-up for server-initiated calls. Keep the existing port intact. Propose a capability check for remote hang-up and project application-visible status from verified persisted call events. [SDK Voice operations](https://github.com/AfricasTalkingLtd/africastalking-node.js/blob/master/lib/voice.js)

The developer Voice overview returned HTTP 403 during review. The findings above come from the provider's official SDKs and Help Center. No live provider requests were made.

## Configuration foundation and QA

The proposed [additive migration](../packages/database/prisma/migrations/20261120130000_voice_provider_configuration/migration.sql) creates a platform-owned table with one row per environment, an authenticated ciphertext envelope, credential verification metadata, enablement and an optimistic write version. Updates and identity audit records commit in one transaction. A stale verification result cannot update a replaced credential. Keep `VOICE_CREDENTIAL_ENCRYPTION_KEY` in the API's secret configuration as a separate base64-encoded 32-byte key. Retain the key with the encrypted data. Changing the key without re-encryption requires replacing the stored credentials.

After the migration is reviewed and approved for an isolated target, configure the key through the approved secret workflow and start the API and admin app against that target. Sign in as Platform Owner and open **Settings → Voice Providers → Africa’s Talking**. Select Sandbox, enter the sandbox application key and provider-issued number, and save. Confirm the replacement field is blank on reload and the production configuration is unchanged. With separate approval for provider access, use **Test Connection** and check the displayed credential result. Activate, deactivate, and replace the credential to confirm that replacement disables the configuration and clears verification. In **Technical → Providers**, verify that each environment shows its own status and that routing remains unavailable.

Enablement records Platform Owner intent. The foundation has no dispatch or callback route. Live activation remains a separate integration step requiring verified Voice readiness.
