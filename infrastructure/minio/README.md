# Private MinIO object storage for Truevine Voice audio

Status: proposed, pending production approval. No production change has been made.

## Architecture

- MinIO runs on the existing Contabo VPS as a systemd service.
- S3 API listens on `127.0.0.1:9000` only.
- Console listens on `127.0.0.1:9001` only.
- Nginx does not expose either port.
- The NestJS API connects to `http://127.0.0.1:9000` using a restricted service account.
- Bucket: `truevine-voice-audio`, private, no public access.
- Object keys are generated by the API and include the organization id.
- Audio bytes are never stored in PostgreSQL.

## Resource assessment

- Disk: 96 GB total, 21 GB available. Audio limit is 10 MB per file and 5 minutes duration.
- Memory: 7.8 GB total, ~6.4 GB available. MinIO idle footprint is small.
- CPU: 4 cores. MinIO is I/O bound for this workload.
- No Docker is available; use systemd.

## Production changes required (approval needed)

1. Install MinIO binary and `mc`.
2. Create the `minio` system user and `/var/lib/truevine-voice/minio`.
3. Create `/etc/truevine/minio.env` with strong generated credentials.
4. Install and enable `infrastructure/minio/minio.service`.
5. Create the private bucket and a restricted service account.
6. Add `AUDIO_STORAGE_BUCKET`, `AUDIO_STORAGE_REGION`, `AUDIO_STORAGE_ENDPOINT=http://127.0.0.1:9000`, and `AUDIO_STORAGE_FORCE_PATH_STYLE=true` to the API environment.
7. Restart `truevine-api` and verify `/health` and audio upload/playback.

## Security controls

- Loopback-only listeners.
- No public bucket or anonymous access.
- Restricted service credentials stored in the deployment secret manager.
- API-side authorization and tenant scoping for every operation.
- Short-lived signed playback URLs from the S3 adapter.
- File size, MIME and container validation in the API.
- Path traversal prevented by server-generated object keys.

## Backup and recovery

- Back up `/var/lib/truevine-voice/minio` with the existing server backup process.
- Database metadata and objects must be restored together.
- Test restore in a disposable environment before production use.

## Disk usage assessment

- `/var/www/TruevineVoice/releases` contains about 60 historical releases (1.1 GB each, ~57 GB total).
- `/var/www/TruevineVoice/incoming` contains about 926 MB.
- `/var/log` uses about 844 MB.
- `/var/lib` uses about 261 MB.
- No application-level audio data is stored yet.
- Recommended conservative audio quota: 5 GB initially.
- Minimum free-space threshold: 10 GB. Alert at 15 GB free and page at 10 GB free.

## Backup assessment

- No database or object backup files were found under `/var/backups`.
- Application releases are retained, but they are not a data backup.
- Before MinIO production use, configure encrypted off-server backups of PostgreSQL and `/var/lib/truevine-voice/minio`.
- Retention recommendation: 14 daily, 4 weekly, 3 monthly backups.
- Restore must be tested in a disposable environment before production reliance.

## Monitoring

- Alert when free disk drops below 15 GB.
- Alert when MinIO or API health checks fail.
- Track bucket size and object count.
- Review release retention periodically; keep only the last 5-10 releases after a successful deployment.

## Binary verification

- Install MinIO only from the official MinIO release channel.
- Verify the downloaded binary checksum against MinIO's published checksum.
- Pin a tested MinIO release and document the version in this directory.

## Systemd hardening note

- The proposed unit uses loopback listeners and a dedicated `minio` user.
- `ProtectSystem=strict` with `ReadWritePaths=/var/lib/truevine-voice/minio` allows object writes while protecting the rest of the filesystem.
- The service must be tested with a reboot and a failed-disk simulation before production reliance.
